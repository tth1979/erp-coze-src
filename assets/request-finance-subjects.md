【里程碑】财务管理 - 会计科目与凭证管理子模块
以现有凭证底座（fin_voucher_templates / fin_vouchers / fin_voucher_lines，已实现五套自动模板+幂等+红冲）为基础，补齐「会计科目实体可维护管理 + 凭证管理子模块增强」，让财务账务口径闭环。本期不对既有模块做破坏性改动。
一、会计科目管理（新增可维护实体）
1. 新增科目字典表（建议 fin_subjects 或账务字典表，RLS 全开，幂等迁移，独立编号文件如 db/migrations/0015_account.sql，不改既有迁移）：字段含 subject_code(科目编码,唯一)、subject_name、category(科目类别:资产1/负债2/共同3/权益4/成本5/损益6)、parent_code(上级)、direction(余额方向 借0/贷1)、is_leaf(是否末级)、balance_flag、status(启用/停用)、sort_no 等。
2. 科目层级：支持多级，非末级科目不可直接用于凭证分录（分录只能挂末级科目，服务端强制校验）。
3. 期初余额：允许配置科目期初余额（年初/当前期间借或贷方向）。
4. 种子预置常用科目，与既有凭证引擎科目编码对齐：库存现金/银行存款、应收账款/预付账款、1405 库存商品、1402 在途物资、1406 发出商品、1901 待处理财产损溢、固定资产/累计折旧、应付账款/预收账款、应交税费-进项/销项、应付职工薪酬、实收资本、未分配利润、生产成本(5101)、主营业务收入/成本(6001/6401)、销售/管理/财务费用、营业外收支。 保留科目字典为唯一账务来源的原则。
5. CRUD + 分页 + 关键字/类别/状态筛选 + 编码唯一 409；有分录引用或已有余额的科目不可删除（业务拒绝），可停用。权限沿用 fin.read / fin.write（admin+manager 可写，staff 只读，匿名 401）。
二、凭证管理子模块增强
1. 凭证列表增强：按期间(会计期间/凭证日期)、科目、摘要关键字、状态(全部/已过账/草稿/已红冲)筛选；分页。
2. 凭证详情：展示借贷明细行（科目编码/名称/摘要/借方/贷方），借贷合计相等展示，状态徽章。
3. 过账流转：草稿 draft → 审核 → 已过账 posted（过账后锁定）；支持对已过账凭证红字冲销（自动生成等额反号红冲凭证），未过账草稿支持删除/作废。沿用既有幂等 UNIQUE(event_type,event_id) 与 CHECK(total_debit=total_credit)。
4. 科目余额表：按会计科目维度汇总期初余额、本期借/贷发生、期末余额（借/贷），支持按期间查询，支持明细科目与上级科目汇总展示（科目余额平衡：明细科目合计 === 上级/总账余额）。
5. 试算平衡表：全科目列示，借贷合计必须由明细行实时汇总（禁止写死），借贷必等；不平衡时展示差额定位。复用四项校验口径（借贷相等、科目余额平衡、勾稽一致、前置单据完成，真实计算）。
6. 前端：/finance/subjects（科目字典管理页，树/表结构+增删改+期初余额编辑）、/finance/vouchers 增强（筛选/详情/过账/红冲）、/finance/balances（科目余额表）、/finance/trial-balance（试算平衡表），响应式，沿用既有视力规范与权限点。
